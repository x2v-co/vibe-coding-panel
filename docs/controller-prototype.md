# 手机外设最小原型（macOS / Codex App）

**日常使用请看 [快速开始](controller-quickstart.md)**；以下保留技术说明和分阶段验证记录。

本原型位于 `spike/mobile-desktop-controller`，默认关闭，不改变原 Panel 的任务执行方式。
手机可边录音边交给电脑常驻 Whisper 识别，文字持续更新预先绑定的 Codex App 草稿；
手机再点发送，通过定向 Return 提交。确认同一会话输入框清空后保留绑定，可继续下一句。
手机不展示会话回复。这不是原生流式 ASR、完整 Micro，也尚未支持 Claude/CLI。

## 启动

要求：macOS、Swift/Xcode Command Line Tools、运行中的 Codex App、辅助功能权限。
沿用 Panel 现有本地 Whisper/ffmpeg 配置；没有语音组件仍可测试文字输入。
在仓库根目录执行，标题必须与专用测试会话一致且唯一：

```sh
PANEL_API_PORT=8897 \
PANEL_DESKTOP_CONTROLLER=1 \
PANEL_LIVE_SPEECH=1 \
PANEL_LIVE_PYTHON=/Users/kl/miniconda3/bin/python \
PANEL_DESKTOP_THREAD='确认任务已就绪' \
PANEL_DEVICE_STORE=.vibe-panel/controller-devices.json \
PANEL_RELAY_STATE=.vibe-panel/controller-relay.json \
PANEL_RELAY_URL=https://vibe.tooluse.app \
node scripts/connect-relay.mjs
```

`PANEL_LIVE_PYTHON` 应指向已安装 Whisper、torch、numpy 的 Python；上面是本机路径。
增量模式使用常驻 `small` 模型，首次下载/加载期间须等待就绪；关闭增量模式仍可使用原有整段转写。
新增本地人声检测依赖（在上述 Python 环境中安装）：

```sh
python -m pip install onnxruntime
python -m pip install --no-deps silero-vad==6.2.1
```

直接加载包内的 Silero ONNX 模型，只依赖 numpy/onnxruntime，不使用 torchaudio 或远程下载器。

使用独立身份和端口，不会替换正式 Connector。端口已占用时不要再启动第二份。
已有原型服务运行时，直接使用下述地址。仅本地测试可运行 `server/index.js`，
指定同样的功能开关、会话标题和端口，额外设置 `PANEL_REQUIRE_PAIRING=1`。

## 使用

1. 在 Codex App 中选好测试会话，清空草稿并点击输入框。不要切到其他 Codex 会话。
2. 在电脑的外部浏览器打开 `http://127.0.0.1:8897/api/desktop-controller/view`，展开
   「电脑绑定与连接」，点击「在这台电脑绑定」。已有草稿时可点「绑定此会话并保留电脑草稿」，
   将现有文字纳入精确草稿检查，不会清空输入框。使用外部浏览器避免抢走 Codex 的应用内输入焦点。
3. 手机先打开 Connector 的 `/app?relay=...` 链接选择这台测试电脑；然后在同一浏览器打开
   `https://vibe.tooluse.app/api/desktop-controller/view`。未配对时页面直接显示配对码输入框，
   输入电脑生成的新码并点「在这部手机完成配对」。成功后表单消失并显示绑定状态。
   已经在主面板配对的手机无需重复输入。不要用另一个浏览器或无痕窗口打开第二个地址。
4. 手机点「刷新连接」，默认勾选「边说边更新电脑草稿（实验）」，开始录音后每约 3 秒提交累计音频，
   转写会修正并更新电脑草稿。检测到人声后停顿约 1.5 秒会自动结束，因每 3 秒取样与推理有额外延迟；
   也可手动结束。等最后一次识别完成，检查电脑草稿，再点发送。
   取消勾选可退回整段录音转写，也可展开「文字输入备用」。录音上限 60 秒。
5. 确认同一会话输入框清空后，发送保留绑定，可继续下一次输入，无需重新绑定。
   写入/发送前确认目标暂时不可用（包括锁屏、切换会话、输入框失焦）时保留绑定和草稿；
   解锁并切回原会话、点击输入框，再从手机手动重试。新文字尚未写入时，点发送会先写入最新文字。
   无法确认发送、绑定身份变化或草稿被电脑改动时仍会撤销绑定。发送键投递不代表 Agent 已完成，
   结果要看电脑。网络失败不要重复发送，先检查会话记录。

关闭原型进程即可停用，没有修改 Codex 配置。不要将未审查的实验版本作为正式服务发布。

## 技术边界

- HTML 是公开的配对页面，不含任何会话状态；状态和控制接口始终要求远程配对，
  即使普通 Panel 未要求配对。配对使用现有一次性码交换，权限并未放开。
- 绑定只允许电脑本地发起。远程只支持 write/send，不允许选择任意应用、键码或会话。
- 会话标题、侧栏样式、Codex 进程和侧栏会话的 ChromeAXNodeId 共同检查目标；
  不再绑定会被重新创建的输入框节点。每次重新查找输入框，并精确比较原草稿后写入。
  AX 图遍历去重，避免共享/循环子节点导致误报界面过深。
- 当前 AX 依赖 `Do anything` 等特定版本的界面标签；同名会话、多窗口、界面变化会拒绝操作。
- 版本号防旧转写覆盖，事件 ID 防重复发送，原生异常后撤销绑定，不自动重试。
- 检查与系统事件之间仍有竞态，不能承诺用户同时切换 App 内会话时绝不串线。
  本原型仅用于人工监督的测试会话，稳定会话绑定仍需改进。
- 手机刷新不读取电脑草稿正文；只拿绑定状态/是否有草稿。回复不传到手机。
- 启动阶段使用 Swift 解释执行；可手动编译脚本并用 `PANEL_DESKTOP_BINARY` 指向二进制。
  这可能改变 macOS 辅助功能授权身份，必须重新验证。

## 杂音和目标恢复修复（2026-09-11）

- 音量阈值不能区分杂音与人声；现在先用 Silero VAD 判断人声并裁掉头尾非人声，
  Whisper 再过滤高无语音概率、低平均置信度或高重复率片段。无有效人声时不生成新草稿。
- 首段有效人声之后出现持续 1.5 秒非人声，固定这一句话的结束位置，不把后续噪声加入识别。
  这是语音活动检测，不是说话人识别：电视声、旁人讲话仍可能被接受，低声或极短的话也可能漏掉。
  普通整段录音备用路径未增加这些过滤；默认勾选增量模式时生效。
- 修复了所有原生错误都撤销绑定的问题：仅明确发生在任何写入/按键前的目标不可用错误可恢复。
  系统事件发出后或读回失败仍撤销绑定，事件重放不会自动重发。
- 实际 AX 检查发现目标侧栏未选中；随后系统锁屏，已增加独立锁屏提示。
  新版真实切换恢复复测需在电脑解锁后进行，不能用协议测试代替真机结论。
- 验证：Node 完整套件 94 项（93 通过、1 跳过）；Python 人声过滤 3 项通过；Swift 类型检查通过。
  本地合成中文样本、静音、随机噪声、单音和语音后接噪声用于验证过滤，尚非手机真实嘈杂环境验收。

## 低音量转写被误过滤（2026-09-11）

复现：将同一中文样本音量降为 0.5%（约 -64 dB RMS），VAD 仍检测到人声，Whisper 正确返回整句话，
但 no_speech_prob 为 0.865、平均 logprob 为 -0.268；旧版独立的 0.5 无语音阈值将文字全部丢弃。
现在对于 VAD 已接受的音频，结合文字置信度判断；高置信度文字可通过无语音概率检查，
低置信度和高重复片段仍拦截。该样本修复后通过，更低音量的低可信片段仍拒绝。
这证明存在此缺陷，尚不能据此断言手机此次失败必然由同一原因造成。

识别响应和受保护的语音状态增加最近一次阶段诊断：音频时长、人声时长、音量及拒绝原因，
不保留录音或转写正文。手机区分无音频、无声音、无人声、文字被过滤和识别器无结果。
新版完整 Node 测试 96 项（95 通过、1 跳过），Python 4 项通过；手机真机仍需复测。

## 最小可用流程收敛（2026-09-11）

- `npm run controller` 设置独立端口和配对身份、检测可用语音环境并启动 API 与 Relay Connector；
  已有服务时复用，不接管占用端口，不要求无关的 CLI 登录。服务首次启动不再必须指定固定标题。
- 本地 bind 可请求 current，由原生检查读取唯一选中的侧栏会话标题；手机不能触发绑定或换目标。
  绑定后仍验证原有进程/会话节点身份和草稿版本，不会随电脑切换会话自动跟随。
- 本地绑定区加入生成配对码；手机隐藏仅电脑可用的按钮，显示对应恢复说明。
- 同一浏览器标签页使用 sessionStorage 暂存未发文字，刷新后恢复但需人工确认；不自动重放操作，
  发送确认成功或清空后删除。暂存不会跨浏览器/跨设备同步。
- Codex 暂时不可发送时属于未投递的可恢复拒绝，保留绑定，等回答结束后可重试。
- 自动化：Node 103 项（102 通过、1 跳过），类型检查通过。

实机补充验证：通过浏览器按钮绑定当前选中的「确认任务已就绪」；切换到另一会话后写入请求返回 409，
同一绑定仍有效；切回后原文字写入返回 200，原生读回确认草稿逐字未变。未发送或清空用户现有草稿。
手机尺寸浏览器刷新恢复暂存文字，发送按钮保持禁用直到确认写入，无横向溢出。
启动器另有独立集成测试：无 CLI PATH 的新进程可启动 API 与测试 Relay，控制页 200，退出后 API 子进程停止。

## 增量录音最终文本纠错（2026-09-11）

最终 `/speech` 请求带 `final: true`，复用普通 `/api/transcriptions` 的同一个 correctTranscript 实例、
模型配置、技术词保护及超时/失败回退。中间片段不纠错，也不因 VAD 提前检测到结束就重复纠错。
识别与纠错共用 50 秒预算，为 Relay 留出响应时间；纠错后再次验证绑定，防止迟到结果进入新目标。
低可信 candidateText 也纠错，但保持人工核对要求，不升级为自动写入。普通模式保持原行为。
验证：Node 108 项（107 通过、1 跳过）。实际同一纠错提供方将“手机运营测试…收告”修正为
“手机语音测试…收到”，一次测试约 7 秒；这不代表固定延迟或识别准确率保证。

## 默认多段普通录音（2026-09-11）

默认关闭增量选项。普通录音完成后走既有识别、纠错接口，发送 append 指令，电脑端以绑定草稿为基础
追加新段（段间换行）。手机不接收完整电脑草稿；成功追加后清除该段临时文字，不再将整份草稿放在手机。
append 沿用精确草稿比对、版本号和事件去重，按合并后的完整长度检查上限，原生仍执行受保护的 write。
用户可在电脑已有草稿时继续录下一段；发送按钮只在用户点击时提交整份电脑草稿。
最近失败的普通录音保留在本页内存中供显式识别重试，成功识别后释放；不自动重试写入或发送。
手机上的异常修正与手动补充只代表当前新段，刷新暂存不包含已成功追加的内容。

原生追加后，电脑输入框包含两个完整段落，版本依次到 1、2，原有前缀不变。每次成功后手机临时文字清空，
可直接开始下一段。随后按版本保护移除测试文字，原生读回确认恢复原草稿；未发送测试消息。

## 普通模式模型对齐（2026-09-11）

此前复用普通转写接口并不意味着两个进程采用同一模型。实际诊断发现主面板 8811 使用
MLX `mlx-community/whisper-large-v3-turbo-q4`，外设 8897 仍使用 Whisper small。
此外外设运行期间有实验增量请求，可能来自旧页面或勾选的实验选项，无法据此确定具体手机录音路径。

外设启动时读取本机忽略文件 `.vibe-panel/controller-speech.json`，仅允许语音后端、模型和工具路径，
显式环境变量优先。本机配置已对齐主面板；普通主面板启动不受此配置影响。
实验增量后端默认关闭，页面启动显式重置实验勾选状态，避免浏览器恢复旧状态。

重启外设后，两边 diagnostics 均确认 MLX large-v3-turbo-q4，实验 speech/status 为 disabled。
同一份合成语音“查看今天至周一，河北秦皇岛的天气”分别经过两个实际转写接口，均返回
“查看今天至周一,和北秦皇岛的天气。”，说明路径结果一致但仍有同音错字；不代表真实手机准确率验收。
恢复绑定原目标会话只读取现有输入框，未写入或发送测试文本。
